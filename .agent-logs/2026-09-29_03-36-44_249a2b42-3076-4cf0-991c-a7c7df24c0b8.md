Your stack fits this well. I'd make only a few changes, plus one architecture decision we need to settle before writing any code.

## Stack

| Layer | Choice | Notes |
|---|---|---|
| App | Next.js (latest, App Router) + TypeScript | We'll scaffold with `create-next-app@latest` so it's the current version |
| UI | shadcn/ui + Tailwind, dark-first | Higgsfield uses a dark look that puts the media first; we'll match that |
| DB / Auth / Storage | Supabase | Row-level security on every table, so users only ever see their own data. Storage buckets for inputs and outputs. |
| Images | Google Gemini image model ("Nano Banana") | One model covers both text-to-image **and** editing with a reference image, so it's our only image model |
| Video | Google Veo | Text-to-video and image-to-video, and it **generates its own audio** |
| Audio | OpenAI TTS + transcription | TTS for voiceovers, speech-to-text for dictating prompts |
| Deploy | Vercel | |

**One model per feature: agreed.** A choice of models adds UI and code but doesn't make the results any better. We'll look up the current model IDs when we connect each API, rather than guessing them now.

**The key decision: video generation runs as a background job.** A Veo video takes minutes to generate, which is longer than a serverless function is allowed to run. So every generation, including images for consistency, will work like this:
1. Save a `generations` row with status `queued`.
2. Start the job with the provider and save its operation ID.
3. Poll for the result, then save the output to Supabase Storage and set the status to `done` or `failed`.
4. The UI updates live through Supabase Realtime.

This is also what makes the experience feel good: you submit a prompt, a placeholder card appears straight away, and it fills in when the result is ready.

**Credits are essential, not an extra.** The demo will be public and Veo is expensive, so each account gets a credit balance and every generation deducts from it. Higgsfield uses credits too, so it looks authentic as well as protecting your API keys.

## Features

### P0: must ship
1. **Landing page:** a hero section with sample outputs, the features, and sign-up.
2. **Auth:** Google sign-in plus email magic link. Every page in the app requires sign-in.
3. **Create studio (the main screen):** one prompt bar at the bottom with **Image / Video / Voice** tabs, settings for each mode (aspect ratio, number of images, duration), a reference-image upload, and a mic button that uses speech-to-text.
4. **Image generation:** text-to-image, plus **editing** from an uploaded or existing image.
5. **Video generation:** text-to-video and **image-to-video**, with a live status on each card (queued, generating, done, or failed with a retry button).
6. **Voiceover:** text-to-speech with a choice of voices, producing a playable, downloadable file.
7. **Library:** your full history as a masonry grid, filterable by type. Clicking an item opens a detail panel with the prompt and settings, **Download, Delete, Reuse prompt**, and chaining actions such as **"Animate this" (image → video)** and **"Edit this"**.
8. **Credits:** a balance in the header, a cost shown on the generate button, and a clear message when you run out.

### P1: if time allows
- **Presets:** Higgsfield's signature feature. Style presets for images and camera-movement presets for video (dolly-in, orbit, crane, and so on). Each one is a small card with a thumbnail that adds curated wording to the prompt behind the scenes. They're cheap to build and make a big impression.
- **Prompt enhance:** one click to rewrite a short prompt into a detailed one using Gemini text.
- **Explore feed:** a public gallery of outputs users chose to share, with "Try this prompt".
